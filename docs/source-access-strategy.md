# Доступ к российским внешним источникам

Актуально на 31 августа 2026 года. Этот документ фиксирует политику транспорта,
результаты живой проверки и рекомендуемую схему MVP.

## Политика проекта

1. API включается только для источника с подтверждённым бесплатным production-доступом.
2. Платный или договорной API по умолчанию выключен. JSON, который публичный
   frontend получает без авторизации и оплаты, допускается как транспорт с
   контролем схемы и резервным HTML/browser-парсером.
3. Для публичных страниц используется HTML-парсер с ограничением частоты, кэшем и
   сохранением сырого снимка.
4. При `401`, `403`, `429`, CAPTCHA или явном challenge парсер повторяет запрос через
   уже запущенный CloakBrowser. CAPTCHA проходит оператор в сохранённом профиле.
5. CDP нельзя публиковать в интернет. Он слушает loopback на том же узле, где работает
   collector, либо доступен только через закрытый туннель.

Переменная `FREE_API_SOURCES` по умолчанию пустая. Добавлять в неё провайдера можно
только после проверки документации, лицензии и бесплатной квоты для production.

## Результат живой проверки

Проверка выполнена из Docker Desktop на локальном Windows-хосте:

| Источник | Результат |
|---|---|
| ЦДТ: список и полные карточки | HTTP 200; импортировано 243 активных текстово подтверждённых лота публичного предложения |
| ГИС Торги | timeout с текущего маршрута |
| TBankrot / Heveya | HTTP 200; доступны как резерв для парсинга |
| ГИР БО | Публичный поиск доступен; массовая выгрузка/API относятся к подписке |
| «Прозрачный бизнес» | Публичный поиск отвечает, но действующий протокол карточки надо зафиксировать через браузер; старый предполагаемый endpoint карточки возвращал 500 |
| КАД | На последнем запросе текущий маршрут получил HTTP 451; нужен российский маршрут/CloakBrowser |
| Telegram API | HTTP 200 |
| ЕФРСБ / Федресурс | HTTP 401 |
| ЕГРЮЛ | Бесплатный поиск и скачивание официальной PDF-выписки сработали; canary выявил явные adverse-факторы |
| ФССП | Публичная форма доступна нестабильно и требует browser/CAPTCHA flow; подтверждённого бесплатного API нет |

Локальный CloakBrowser успешно поднял CDP на `127.0.0.1:9222`, но публичный список
ЕФРСБ также вернул HTTP 401. Следовательно, браузерный fallback настроен, а текущий
блокер находится на стороне источника или сетевого маршрута.

По бесплатному поиску ЕГРЮЛ ФНС можно подтвердить точное совпадение ИНН, названия и
ОГРН, но строка поиска часто не содержит жизненный статус организации. Воркер при
наличии токена запрашивает официальную PDF-выписку ограниченным циклом и извлекает
только явные признаки: недостоверные сведения (`invalid`) и решение о предстоящем
исключении (`pending_exclusion`). Если таких маркеров нет, статус не угадывается:
скоринг добавляет gap `debtor_status_missing`; просроченная или неподтверждённая
идентификация по-прежнему блокирует сигнал. Для `invalid` и `pending_exclusion`
установлены отдельные stop-факторы.

## Фактически работающая схема MVP

```text
ЦДТ public JSON + прямые адаптеры других ЭТП
        |
        v
JSON/HTML parser -> CloakBrowser fallback -> текстовая валидация -> PostgreSQL/API
                                                   |
                                                   v
                                      scoring, web, Telegram
```

По умолчанию приложение запускается с `INGEST_SOURCES=cdt`. Публичный список
ищется по словам `дебитор` и `требован`, дубликаты объединяются по `tradeId`, а
полная карточка повторно проверяется по словарю дебиторской задолженности. Так
ложная категория площадки не превращается в ложный лот радара. Чтобы снова
подключить ЕФРСБ без остановки работающего импорта, используется
`INGEST_SOURCES=cdt,efrsb`.

### Вариант A: collector на текущем компьютере

Подходит для первого MVP без дополнительной оплаты. PostgreSQL и приложение работают
в Docker, а `ar-radar ingest`/`enrich` запускаются из локального Python-окружения,
которое видит `127.0.0.1:9222`. Недостаток: сбор зависит от включённого компьютера.

### Вариант B: collector на российском VPS

Рекомендуется для непрерывной работы. На VPS размещаются collector и CloakBrowser;
основной API может остаться на другом хосте. Между ними передаются только
нормализованные записи через закрытый authenticated endpoint или приватную сеть.
Подходящие инфраструктурные варианты: [Selectel Cloud Servers](https://selectel.ru/services/cloud/servers/?section=prices),
[Timeweb Cloud](https://timeweb.cloud/) и
[Cloud.ru VM с Docker](https://cloud.ru/docs/tutorials-evolution/list/topics/free-tier-vm__docker).

### Вариант C: весь стек на российском VPS

Самая простая сетевая схема для MVP: `docker compose`, PostgreSQL, collector и браузер
на одном узле. Минусы: резервные копии, обновления и мониторинг полностью на владельце.

## Эксплуатационные правила

- Для каждого домена отдельные rate limit, timeout и circuit breaker.
- Повторять запросы с экспоненциальной задержкой; `401/403/429/503` не превращать в
  пустой успешный результат.
- Сохранять `source_url`, время снимка, хэш и typed-код ошибки.
- Кэшировать ЕГРЮЛ/КАД/ФССП минимум на сутки, если источник не требует более свежих данных.
- Проверять конечный URL после браузерных редиректов по allowlist.
- Не передавать CDP наружу и не хранить токены в репозитории.
- Диагностика `/api/v1/diagnostics/sources` показывает разницу между транспортной
  ошибкой, challenge и ответом источника.

## Приоритет дальнейшего подключения источников

1. Сохранять ЦДТ рабочим первичным seed и ежедневно контролировать структуру JSON.
2. Проверить ГИС Торги с российского маршрута: list/RSS/open-data JSON, покрытие
   дебиторской задолженности и стабильность схемы.
3. Подключать прямые карточки Альфалот, Lot-online, Сбербанк-АСТ, МЭТС и Фабрикант: бесплатный
   публичный JSON — напрямую, в остальных случаях HTML-парсер и CloakBrowser.
4. Добавить TBankrot и Heveya только как резерв обнаружения пропущенных карточек;
   факты цены и срока по возможности подтверждать на исходной ЭТП.
5. Вернуть ЕФРСБ в активную конфигурацию после восстановления публичного маршрута
   либо заключения договора на REST. Его отказ не должен останавливать другие источники.
6. Реализовать адаптеры «Прозрачного бизнеса» и ГИР БО, метрики успешности и возраста
   данных. После этого провести суточный canary уже на потоке реальных лотов.
